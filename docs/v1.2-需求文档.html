iPhone 投屏与 TCHESS 本地象棋助手需求文档

版本：1.2　日期：2026年10月15日

采用现成开源软件搭建本地象棋分析工具：iPhone 将棋盘画面投屏到 Windows 电脑，TCHESS 识别投屏窗口中的局面，皮卡鱼使用本机 CPU 计算，在电脑上显示建议走法。用户在手机上自行落子，不需要每一步手动截图。

本版采用电脑查看提示的使用方式，优先完成软件安装、配置与兼容性验证。此前独立开发 iOS App 的路线暂缓；本次不包含云服务器配置或万相视频项目。

项目目标与范围

第一版需要完成连续投屏、棋盘识别、本地引擎分析和电脑端提示，并使用户能够自行启动、停止和恢复整个流程。

  • 使用场景新增：个人练习使用。用户在 iPhone 上自行落子，电脑显示引擎建议；工具不操作手机。
  • 使用 TCHESS 的现成发行包，优先通过设置解决问题。
  • 引擎使用本地皮卡鱼，不接入语言模型，不做中文棋理讲解。
  • 提示可以包含箭头、起点终点和“炮二平五”等走法记号。
  • 使用观战分析模式，不配置自动落子或自动续盘。
  • 不开发苹果安装包，不处理自研 App 签名；所选投屏工具如需手机端应用，按该工具自身安装要求处理。
  • 第一版仅覆盖本地使用，不建设账户系统、公网接口或远程访问服务。
  • 已知方案限制新增：建议显示在 TCHESS 自己的棋盘上，不叠加到投屏画面；用户需对照两个窗口。中途连线时 TCHESS 只获得当前局面，没有此前着法历史，重复局面、长将长捉的判断可能不准确。

软件选择与已知能力

TCHESS 项目提供引擎加载、棋局分析和连线功能。使用手册说明观战模式只分析局面，并支持棋步箭头、CPU 线程和思考时间设置。优先从项目 Releases选择适合 Windows 的现成版本；具体包及运行依赖在安装时核对。

TCHESS 已知信息新增：

  • 基于 Java（JDK 21）与 JavaFX 23 开发，许可证 GPL-3.0，作者声明未经授权禁止商业用途。安装时核对发行包是否自带运行环境，不自带则将对应 JRE 一并放入固定目录。
  • 连线分前台和后台模式：前台要求目标窗口不被遮挡；后台模式并非所有平台都支持。
  • 可调设置包括识别扫描间隔（毫秒）、识别线程数和动画确认。棋子有移动过渡动画时需开启动画确认，否则可能识别错误。
  • 手册未说明识别原理（模板匹配或模型、是否需要框选棋盘）。项目开源，正式测试前阅读相关源码，以便判断识别失败原因和可能的改动范围。

皮卡鱼 Pikafish负责计算走法。安装时选择适合本机 CPU 的 Windows 版本及配套网络权重，并记录版本和文件路径。

棋规设置新增：皮卡鱼默认采用亚洲规则，需在引擎选项 Repetition Rule 中按 JJ象棋 实际规则设置（中国规则为 ChineseRule），保存后重载引擎。规则不一致时，引擎可能推荐在 JJ 中被判负的循环着法。

投屏软件尚未选定，要求支持用户实际 iPhone 与 Windows 环境，能够连续呈现清晰棋盘。优先验证本地传输方案，并核对收费、时长限制、画面水印和是否需要额外手机端应用。

投屏候选方案新增：Windows 不自带 AirPlay 接收能力，需要第三方方案。

类型候选优点风险与核对点
AirPlay 接收端UxPlay（开源）、AirServer、LonelyScreen、5KPlayer无线；手机端无需安装应用依赖局域网发现；有一定延迟，偶有卡顿；核对收费、水印、时长
第三方应用投屏LetsView、ApowerMirror 等部分支持有线需手机端应用；常见水印、时长限制、登录要求
HDMI + 采集卡——延迟最低，画面最稳定不采用：用户已确认不购买硬件。无采集卡时有线投屏到 Windows 实际不可行，本项目按无线方案执行

方案优先级（用户已确认：必须免费，优先开源）：首选 UxPlay（开源 AirPlay 接收端，GPL，无水印无时长限制；Windows 下可能需要自行编译或寻找可靠的第三方打包，这是第一步实测内容）。UxPlay 走不通时，再从免费闭源接收端中按“无水印、无强制登录、时长可接受”筛选。无线识别不稳定时，在当前约束内通过调整分辨率、路由器连接方式（电脑有线接路由器）和扫描参数缓解，并如实记录达到的稳定程度。

TCHESS 的屏幕识别能力不等于已经适配 iPhone 投屏中的 JJ象棋。该组合的画面采集、棋子识别及延迟，需要用实际设备验证；识别不通过时先调整显示设置，再评估是否需要局部改造。

设备与部署要求

电脑为现有 Windows 笔记本（已确认），CPU 为 AMD Ryzen 9 7945HX，16 核 32 线程；安装时补充记录系统版本、可用内存及磁盘空间。软件和引擎文件保存在固定本地目录，避免移动后配置失效。

电脑设置新增：

  • Windows 显示缩放固定（建议先用 100% 测试），记录缩放值；非 100% 缩放可能导致截图坐标偏移。多显示器时投屏窗口放在主显示器。
  • 笔记本使用期间接通电源，电源模式选高性能，合盖操作设为“不执行任何操作”，关闭自动睡眠；记录长时间运行后是否因发热降频。
  • TCHESS 会截屏并具备模拟鼠标能力，可能被杀毒软件拦截，必要时将安装目录加入信任列表。
  • 记录所有下载文件的来源地址与 SHA256。

iPhone 为 16 Pro Max（USB-C 接口），iOS 26.6，游戏竖屏使用（已确认）。无线投屏在同一局域网测试，电脑尽量有线连接同一路由器以减少无线干扰。

网络排查：用户已确认未开 AP 隔离。仍需核对：手机与电脑在同一网段（不在访客网络）；Windows 防火墙放行投屏接收程序；部分接收端依赖 Bonjour 服务。

iPhone 端准备新增：

  • 开启勿扰或专注模式，避免通知横幅和来电遮挡棋盘。
  • 自动锁定设为“永不”，防止熄屏中断投屏。
  • JJ象棋 中关闭不必要的动态特效，固定横屏或竖屏。
  • 可选：使用“引导式访问”将手机锁定在 JJ象棋 内。

使用期间电脑保持开机和唤醒。象棋识别与分析不依赖云端 GPU 或自建云服务器；关闭 TCHESS 中的云库查询，保留本地引擎分析。JJ象棋自身的联网需求不属于本工具的计算依赖。

使用流程

  1. iPhone 开启勿扰模式，确认屏幕不会自动锁定。
  2. 打开电脑上的投屏工具，将 iPhone 棋盘画面显示在电脑上。
  3. 打开 TCHESS，确认本地皮卡鱼已正确加载，棋规设置正确。
  4. 固定投屏窗口大小和位置，保持棋盘完整、清晰且不被遮挡。
  5. 在 TCHESS 中选择观战模式并连线到目标棋盘，核对红黑方向、棋子位置及行棋方。
  6. 用户在手机操作，电脑随画面变化更新局面和建议。
  7. 发生识别错误、投屏冻结或弹窗遮挡时，暂停参考提示，恢复画面后重新识别。
  8. 使用结束，停止连线并关闭分析与投屏程序。

功能要求

连续画面输入：用户启动一次投屏后，应持续看到棋盘变化，无需每步截图或上传图片。投屏窗口尺寸变化后需要重新确认识别区域。优先测试前台采集；后台采集只有在当前投屏工具上验证通过后才启用。投屏窗口通常由显卡渲染，后台截图可能得到黑屏，因此后台模式列为可选项新增。

局面识别：能够识别测试使用的 JJ象棋皮肤、红黑棋子和方向，并跟随吃子及移动更新。对动画过渡导致的误识别，尝试调整扫描间隔及动画确认设置。以人工对照实际棋盘确认识别正确为准，不能仅以“连线成功”判断。

稳定局面定义新增：走子动画结束、棋子回到格点、无弹窗遮挡时的画面视为稳定局面。以下情况需单独测试是否被误识别为局面变化：选中棋子的高亮、上一步标记、将军提示、悔棋、对局结算弹窗、头像与计时条贴近棋盘边缘。

引擎分析：能够加载本地引擎，设置线程、内存和思考时间，并稳定返回走法。先从保守资源设置开始，测试电脑响应与耗时后调整，不默认占满所有线程。初始参数建议新增：7945HX 支持 AVX-512，优先选用皮卡鱼 avx512 或 vnni 版本；线程 8–12，Hash 256–512MB，思考时间固定 1–1.5 秒，再根据实测调整。

结果显示：在电脑的 TCHESS 界面显示当前局面及建议。建议必须与当前稳定局面一致；旧画面的建议不能视为当前提示。现成软件对冻结、断线和过期结果的处理需要验证，存在不足时在操作说明中明确暂停和恢复步骤。执黑时核对 TCHESS 棋盘方向与走法记号视角（如“炮二平五”与“炮8平5”），在操作说明中写明如何阅读新增。

配置保留：保存引擎路径及相关参数，重启后可恢复使用。投屏及连线设置是否自动保存应实测；不能保存的步骤写入启动说明。实测 TCHESS 配置文件的存放位置并写入备份说明新增。

建议验收标准

以下指标作为首轮试用验收目标，尚非已有性能结果。

  • 安装与引擎：软件正常启动，皮卡鱼能对至少 3 个已知局面返回合法走法；关闭云库后仍能分析；棋规选项已按 JJ象棋 规则设置。
  • 投屏：连续运行 20 分钟，手机落子在电脑可见，无需人工逐步截图。
  • 识别：至少检查 20 个稳定局面，包含红黑方向、吃子、开局和中残局；逐个核对全部棋子及行棋方。发现错误时不得记为通过。
  • 同步：连续观察至少 30 次局面变化，记录漏识别、错误局面和旧提示。建议以稳定画面出现后 3 秒内显示匹配建议为初始目标；未达到时记录实际耗时及原因，决定调参或调整目标。
  • 异常恢复：测试停止投屏、遮挡窗口、调整窗口大小及断开网络。恢复后能够重新连线，并人工确认当前局面正确。
  • 本地运行：不启动云服务器，完成投屏、识别和分析。程序不自动操作手机落子。

延迟预算新增：3 秒目标拆分记录，便于定位瓶颈。

环节初始预算调节手段
投屏传输（手机画面到电脑窗口）≤ 0.5 秒更换投屏方案、有线连接、采集卡
识别（扫描间隔 + 动画确认）≤ 1 秒扫描间隔、识别线程、动画确认

测试方法新增：使用 OBS 同时录制投屏窗口和 TCHESS 窗口，事后逐帧统计延迟、漏识别和旧提示，录像作为测试记录保留。测试样本按“棋盘皮肤 × 执红/执黑 × 开局/中局/残局 × 动画确认开/关”组合覆盖。

记录投屏工具版本、TCHESS 版本、皮卡鱼版本、棋盘皮肤、窗口尺寸、Windows 缩放比例和引擎参数，使后续能够复现测试条件。

实施步骤与交付物

第一步，核对 iPhone 与电脑环境，选定投屏工具，先验证手机画面能连续到达电脑。第二步，安装 TCHESS 和皮卡鱼，单独验证引擎并设置棋规。第三步，阅读 TCHESS 识别相关源码，连线实际投屏棋盘，调整识别设置并完成验收。第四步，整理日常启动、停止、异常恢复和配置备份说明。每一步完成并确认后再进入下一步。

交付物包括可运行的本地软件目录、记录的软件来源及版本与 SHA256、引擎与连线配置、简短中文操作说明和实际测试结果（含录像）。每一步讲清操作用途、文件位置及预期结果。

若投屏无法稳定识别，先排查分辨率、皮肤、缩放和窗口采集，再尝试采集卡方案。现成配置不能满足要求时，列出具体缺口和最小改动范围，再决定改造；不将安装成功当作整套方案已经完成。
