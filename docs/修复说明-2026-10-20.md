# 采集与识别修复

本次修改源代码，尚未生成或安装新 IPA。

## 已修改

- 采集按钮从安装包读取真实广播扩展 ID，适配重签工具独立改写扩展编号的情况。
- 广播扩展开始后，如果 15 秒未收到视频帧，或连续三次上传失败，结束采集并显示原因。扩展本身无法被系统启动时，这些提示不会执行，仍需检查实际签名包。
- 画中画每半秒独立送入视频帧，不再等待网络请求返回；断线显示连接失败，恢复后重新渲染。
- 识别先定位主棋盘，再裁图识别棋子，避免手机长截图整体缩小后文字太模糊。增加棋子位置合法性检查；不自动猜测非法棋子的身份。
- 未识别到棋盘或局面不合法时清除旧箭头。后台异常显示重试；引擎响应超时后终止本程序启动的引擎，下帧重启。
- 修复监控页面 JavaScript 重复声明变量和字符串换行语法错误。

## 本机验证

在 server 目录运行 `.venv\Scripts\python.exe -m unittest test_regressions -v`：4 项通过。
包含保存截图中“仕误识别为相”的回归、失去棋盘后清空提示、引擎超时和监控页面脚本语法。
真实皮卡鱼引擎完成开局搜索，正常返回着法。
七张历史错误图并非全部识别正确，遮挡和其他误识别仍需更多真实样本验证。

## 使用更新

1. 重启电脑端 server 服务，加载 Python 修改。
2. 使用现有 iOS 构建流程重新构建 IPA，然后签名安装到手机；重启旧 App 不会加载 Swift 修改。
3. 手机先确认 App 显示服务器已连接，再开始采集，切到完整棋盘。
4. 电脑监控页观察帧计数是否增加。若系统录屏弹窗仍转圈且电脑没有收到 start 事件，应继续检查签名后的广播扩展是否存在、是否签名有效，以及手机系统日志。

Windows 环境未执行 Xcode 编译及 iPhone 实机测试，因此尚不能确认系统采集启动转圈已经消除。

## 皮肤适配：第二轮程序优化

- 采集参数由宽 720、JPEG 质量 0.6 改为宽 960、质量 0.8。保持每秒一帧、单请求、不积压；内存占用及实际流量还需 iPhone 实测。
- 彩色识别失败才尝试灰度识别，减少背景色干扰。只有棋子占位及红黑方归属与彩色检测一致、且规则校验通过才接受灰度结果。
- 彩色图未找到棋盘时，尝试使用灰度定位的棋盘区域重新检测彩色棋子，核对位置和红黑归属。没有硬编码预览图棋子身份或位置到正式识别逻辑。
- 本轮没有重新训练模型，没有增加网格线检测算法。

- 新程序配合新采集近似压缩：9/10 完整正确。

之前七张历史错误截图与本轮修改前相比，输出棋盘及通过/拒绝状态均未改变。新增三项灰度回退测试，检查位置变化、红黑变化应拒绝，以及一致位置/颜色的合法候选可接受。
